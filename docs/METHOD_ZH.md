# QPCF 方法中文说明

## 一句话理解

QPCF（Query-aware Provenance-Constrained Fusion，问题感知的来源约束证据融合）
解决的是 RAG 中的知识冲突：检索到的上下文支持一个答案，而大模型自身记忆的知识支持
另一个答案。

它不直接相信某一次生成，也不把所有生成结果简单投票，而是：

1. 从同一个 RAG 样本中获得多个互补的答案信号；
2. 检查这些答案是否真正被“问题 + 检索上下文”支持；
3. 按证据来源进行去重后再融合；
4. 只有多个来源可区分的分支共同支持同一答案时，才修改保守的初始答案。

代码和结果中的版本号是 `UGCP-v5.1-QPCF`，论文正文建议简称 **QPCF**。

## 输入和输出

每个样本包含：

- 问题 `q`；
- RAG 检索上下文 `c`；
- 多个候选答案 `Y`。

方法最终输出一个候选答案。方法在作出决定时不读取标准答案；标准答案只在预测完成后
用于计算 ACC、EM 和 F1。

## 概念边界：什么是断言

本文严格区分“断言”和“模型输出”。**断言（assertion）**是一个陈述性命题：相对于
给定的检索上下文或假设世界，它能够被判断为受支持、被反驳或证据不足。一个文本片段、
图节点或模型分数不会因为被方法使用就自动成为断言。

- **原子断言（atomic assertion）**只表达一个可独立核验的事实，继续拆分会破坏该事实的
  完整含义。它通常可以规范化为主语、关系和宾语，但三元组形式不是必要条件；一元属性
  命题也可以是原子断言。包含两个可分别判真的并列事实的句子不是原子断言。
- **复合断言（composite assertion）**显式连接两个或更多原子断言，例如因果、条件或
  合取关系。复合断言仍可判真，但不能与原子断言混称。
- **证据片段（evidence span）**是从上下文复制或定位出的原文。它提供溯源依据，但只有
  在表达了完整可判定命题时才同时构成断言。
- **答案假设（answer hypothesis）**是待验证的命题“问题 `q` 的答案为选项 `y`”。它是
  候选结论，不是来自上下文的事实断言。
- **答案观测（answer observation）**记录某个 LLM 分支或语义分支选择了哪个选项。它
  描述的是来源的输出，不证明该选项在事实层面为真。
- **语义信号（semantic signal）**包括相似度、NLI 分数及由其选出的选项编号；这些都是
  证据对齐信号，不是断言。

例如，上下文中的“Marie Curie was born in Warsaw”可以构成一个原子断言；原文所在句子
是证据片段；“本题答案是 Warsaw”是答案假设；“验证分支选择选项 2”只是答案观测。

当前 QPCF **不抽取也不遍历事实断言节点**。它的图节点是证据来源、答案观测和候选答案，
因此准确名称是“来源感知的证据图”，而不是“断言图”。SAS 中可借鉴的是“将实体描述拆成
可溯源的原子命题”这一表示原则；若未来采用，它应替换当前句子级证据单元并单独验证，
不能把模型投票改名为断言，也不能作为第五个叠加模块直接加入当前结果。

## 模块一：多视角 RAG 证据生成

英文建议使用 **Multi-view RAG Evidence Generation**。

这一模块让模型从不同角度回答同一个问题：

- **普通 RAG 答案**：按照常规方式阅读问题、上下文和选项，给出一个答案。
- **结构化推理答案**：一次调用同时区分初始答案、上下文支持的答案和模型先验知识的
  答案，并抽取上下文中的原文证据。
- **答案盲验证分支**：出现上下文与先验冲突时，再让验证分支重新阅读完整上下文或抽取的
  证据片段。验证分支看不到前一个分支选择的答案，避免顺着已有答案进行确认。

这里的目标不是通过更多调用堆叠方法，而是显式区分三类常见 RAG 信号：

- retrieved evidence，即检索证据；
- model prediction，即模型当前预测；
- parametric knowledge，即模型参数中记住的知识。

## 模块二：问题感知的证据对齐

英文建议使用 **Query-aware Evidence Grounding**。

仅仅发现“选项中的词出现在上下文附近”并不能说明上下文回答了当前问题。因此方法使用
两个冻结的语义模型：

- **Dense context matching**：MiniLM 判断选项与哪一句上下文最相似，用来获得宽松的
  语义召回信号。
- **Question-conditioned entailment**：NLI 模型判断某一句上下文是否支持“当前问题的
  答案是该选项”，把问题、选项和上下文关系同时纳入判断。

MiniLM 更像 RAG 中的 dense retriever，负责找相关证据；NLI 更像 reranker 或
entailment scorer，负责检查相关证据是否真的支持当前答案。二者都不训练、不更新参数。

## 模块三：来源感知的图证据融合

英文建议使用 **Provenance-aware Graph Evidence Fusion**。

图的结构可以直观理解为：

```text
总入口 -> 证据来源 -> 该来源的观察结果 -> 候选答案
```

一个“证据来源”可以是普通 RAG 调用、结构化 LLM 调用、答案盲验证器、MiniLM 或 NLI。
每个来源最多提供 1 单位支持。这样做是为了防止同一次 LLM 调用输出 BASE、CONTEXT、
PRIOR 等多个字段后，被错误地当成多个模型投票。

这里的“来源可区分”是溯源约束，不代表统计独立。普通分支、结构化分支和验证分支共享
同一个骨干 LLM，输出仍可能相关；图只保证同一次调用的多个字段不会重复计票。

对每个候选答案，方法使用最大流计算有多少条来源族不重叠的路径能够到达它。这个值在
论文中可称为 **multi-source support score（多来源支持分数）**。只有检测到上下文与
模型先验冲突，并且问题条件 NLI 也选择上下文候选时，方法才屏蔽容易携带先验偏差的边。
未经独立语义确认的分歧不会触发边屏蔽。

最终只有一个答案满足以下条件时，图融合才认为证据充分：

- 它拥有最高的多来源支持分数；
- 最高分没有并列；
- 至少有两个来源族支持它。

## 为什么它不等于多数投票

普通多数投票直接统计多少个观察结果选择了 A、B、C 或 D。QPCF 还额外考虑：

- **来源相关性**：同一次调用产生的多个字段只能算一个来源；
- **证据类型**：检索上下文、模型先验、答案盲验证和 NLI 信号具有不同角色；
- **冲突方向**：context-prior conflict 经问题条件 NLI 确认后才屏蔽先验侧路径；
- **保守回退**：支持不足或并列时，不强制选择图中的赢家。

因此，多数投票是必要基线，但不是 QPCF 的等价实现。正式结果中已经保存
`majority_same_budget`，它和完整方法使用完全相同的模型观察，能够直接比较图融合是否
优于普通计数。另一个 `shared_backbone_capacity` 敏感性变体把所有共享同一 LLM 骨干
的调用合并为一个保守来源组，用于量化跨调用相关性可能带来的影响。

## 模块四：保守的冲突感知答案选择

英文建议使用 **Conservative Conflict-aware Answer Selection**。

最终决策分两条统一规则：

1. **普通冲突路径**：如果选项中没有 `I don't know`，先得到
   **context-grounded fallback（上下文感知的回退答案）**；只有图融合被激活且某个答案
   获得唯一的多来源支持时，才更新回退答案。
2. **IDK 充分性路径**：如果选项中存在 `I don't know`，把普通 RAG 答案视为待验证候选。
   只有至少三个不同来源族支持同一个候选时才输出具体答案，否则输出 `I don't know`。

三个来源族的门槛对所有模型和数据集固定，不读取标准答案，也不增加大模型调用。它是一种
常见的 selective prediction / abstention 机制：证据充分时回答，证据不足时明确弃答。

## 一个简化例子

假设模型自身知识倾向选 A，但检索上下文在当前假设世界中明确支持 B：

- 普通 RAG 分支选 A；
- 结构化分支输出 `CONTEXT=B`、`PRIOR=A`，并抽取支持 B 的原文；
- 答案盲验证器重新阅读证据后选 B；
- 问题感知 NLI 也判断上下文支持 B。

结构化分支即使同时输出多个支持 B 的字段，也只能贡献一个来源。此时 B 仍然得到
“结构化分支 + 答案盲验证器 + NLI”等多个来源族的支持，而 A 主要来自普通答案和模型
先验。冲突感知的边屏蔽会削弱先验路径，图融合得到唯一支持的 B，最终决策才把回退答案
更新为 B。

如果只有结构化分支自己支持 B，其他来源都不支持，B 不会因为同一次调用输出了多个字段
而获得虚假的多数，方法会保留回退答案。

## 旧术语怎样理解

部分旧术语只是实现名称；“层次断言图”则会造成对象层级混淆，应停止使用：

| 旧术语 | 推荐说法 | 实际含义 |
|---|---|---|
| 层次断言图 | 不再使用 | 当前图没有事实断言节点 |
| typed observation graph | 多视角证据图 | 保存不同来源分支支持哪个选项 |
| semantic bridge | 问题感知证据对齐 | MiniLM 召回信号加 NLI 支持信号 |
| provenance capacity | 来源级去重 | 同一次调用最多算一个来源族 |
| directional cut | 冲突感知边屏蔽 | NLI 确认上下文候选后移除先验偏置路径 |
| max-flow certificate | 多来源支持分数 | 能到达候选答案的来源族不重叠路径数 |
| scope certificate | 上下文感知回退答案 | 图融合之前的保守答案 |
| risk projection | 置信度门控答案更新 | 证据充分才更新回退答案 |
| IDK guard | IDK 充分性保护 | 至少三个来源族支持后才把“不知道”替换成具体答案 |

论文中可以在方法公式处说明“多来源支持分数通过最大流实现”，但不需要反复使用“证书”
和“投影”描述整个方法。

## 方法可以声称什么

最准确的定位是：

> QPCF 是一种训练免费、标签免费的 RAG 冲突处理方法。它通过问题感知的证据对齐和
> 来源约束的图证据融合，减少同源信息重复计票，并以保守决策门控处理检索证据与模型
> 参数知识之间的冲突。

不建议把它描述成通用知识图谱构建、图神经网络或所有 RAG 任务上的通用 SOTA，因为当前
正式实验针对多项选择式 RAG 冲突评估。
